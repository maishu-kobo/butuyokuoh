# #36 一覧APIのページ取得

対象基準: main `78161507701a4fc2f49919b8cb91cc3670a215c2`。写真登録のJSONオブジェクト応答修正（#254）を含む。PRの向き先は `feature/capture-existing-bugfixes`（基準 `5e075aaf`、親develop、ツリーはmain同一）。main/developへのマージは行っていない。

## 動作

- `/api/items/page` が検索・分類・優先度・比較グループ・6種類の並び順を全件に適用する。詳細と価格履歴は50表示行ずつ取得する。既存 `/api/items` は互換用に維持する。
- 写真比較グループは1表示行として扱い分割しない。このため1ページの商品件数は50を超え得る。巨大な単一グループの上限設定は別課題。
- 件数・合計金額は全体、条件一致件数・全選択は未取得分も含める。価格一括更新も全体IDを使う。写真由来グループの予算対象1件・購入済みとの整合性は既存計算を共有する。
- フィルターやアカウント変更で先頭から取得し、古い応答を破棄する。追加取得中の連打は同じページを二度追加しない。追加取得失敗時は既存表示を保持して再試行する。
- ソート・検索・集計入力がページ間で変化したら409を返し、画面で理由を知らせ先頭から再取得する。同一秒の編集も検出する。変更後の選択を持ち越さない。
- ドラッグの並び替えは「優先度順・条件なし・全件取得済み」でのみ許可する。部分的な順序で未取得商品の位置を書き換えないための意図的変更。位置保存のAPIは既存のまま。

## 残る範囲

これは詳細・価格履歴・初回転送量を小さくする変更で、すべてのDB処理を定数時間にするものではない。日本語並び順・既存検索・集計・全選択との互換性のため軽量索引、予算計算用列、ID配列はO(N)。購入履歴の補助取得は既存のまま。全ページの読込では索引・集計を繰り返す。SQLによる全文索引、全選択用のサーバー操作、隣接位置指定の並び替え、巨大グループ分割は次段階の設計課題。
