# 写真から登録する

会員が「新しいアイテムを追加」から、写真で商品を探し、候補を選んでリストに入れる。初期状態ではオフ。ゲストにはこの入口を出さない。

## 使い方

「新しいアイテムを追加」を開く。

- 「写真から登録」が1つだけある。粗いポインタ（スマホ）では、`capture` の付いていないファイル入力が OS の選択シート（カメラ、ライブラリ、ファイル）を開く。このボタンはメニューとは案内しない。細かいポインタ（デスクトップ）ではメニューが開く。「カメラで撮る」は `getUserMedia` がある安全な画面だけ。「ファイル/写真を選ぶ」はファイルを選ぶ。外をクリックするか Escape でメニューは閉じる。ファイルは JPEG、PNG、WebP、HEIC、HEIF を1枚選ぶ。カードへ1枚ドロップしてもよい。複数枚は受け付けない。
- 送る前に、ブラウザが長辺1600pxの JPEG に縮小する。「写真から登録」とドロップは同じ。縮小しても 5MB を超えるときは「写真は5MBまでです」と出して送らない。ブラウザが HEIC を復号できるときは、その JPEG を送る。復号できないときは、5MB 以内の HEIC をそのまま送り、サーバが JPEG に変えてから判定する。ブラウザが復号できても出来た JPEG が 5MB を超えるとき、元のファイルが 5MB を超えるとき、どちらも「写真は5MBまでです」と出して送らない。宣言された画素が 4000 万を超える HEIF と、画素サイズの書いていない HEIF はサーバが復号しない。読めない形式と、サーバでも解けない HEIC は「この写真は読めません」。追加の画面を閉じると、まだ終わっていない縮小は捨てて、開き直しても判定には送らない。サーバは受け取りの検証、HEIC の変換、縮小、回転、位置情報の除去を行う。判定へ渡すのは JPEG だけ。

進み具合は「写真を送っています」「商品を推定しています」「候補を探しています」と読み上げる。15秒を超えたら、やり直すか手入力を選べる。

確かなときは商品名を1つ、迷うときは3つまでボタンで出す。モデルが商品を判別できないときだけ、撮り直しを案内する。判定の通信や解析が失敗したときは、その場で1回送り直し、それでもだめなら「もう一度判定する」を出す。モデルが unreadable と言ったときは、products が無くても送り直さない。確かな判定のあと店の検索が通信で失敗したときは「もう一度探す」で同じ商品名の検索だけやり直す。読めない写真とは文面を分ける。色の候補をスラッシュで並べた名前は、1つの商品名に整える。確かさは数字にしない。商品名を直したときは、その名前で検索だけやり直す。

Yahoo! と楽天のキーが両方無いときは、「ストア検索のキーが未設定のため候補を出せません。商品名を確認して登録してください」と出し、「この名前で探す」は押せなくする。キーがある店の失敗は、これまでどおりやり直せます。

候補には画像、ショップ名、商品名、価格、取得時刻、商品ページを出す。画像は Yahoo! の `image.medium`（無ければ `image.small`）と、楽天の `mediumImageUrls` だけ。https で、次の配信ホストのものだけを出す。それ以外は画像を出さない。ブラウザが配信元から直接読む。`next/image` の `remotePatterns` も同じホストの https だけにする。サイト全体の img-src は、リストに入っている他店の画像を消すので付けない。

- `item-shopping.c.yimg.jp`
- `thumbnail.image.rakuten.co.jp`
- `tshop.r10s.jp`

取得時刻は日本時間で出す（例: 2026/10/23 09:26）。

商品名自体がケース、カバー、フィルム、保護、ガラス、充電器、ケーブル、ストラップ、対応、用を含まないときは、本体の候補を優先する。Yahoo! の query と楽天の NGKeyword には、ケースなどの除外語を足さない。`-ケース` は「充電ケース付き」のように本体の名前まで店の検索から消す。ジャンルIDや価格の下限では絞らない。返ってきた候補から落とすのは、ケース、カバー、フィルム、充電器、ケーブル、ストラップだけ。本体が一件も無いときは、取れた候補をそのまま出す。店への検索は1回だけで、やり直しはしない。「【機種用】」のような括弧と、「対応」「用」「保護」「ガラス」は本体の名前にも出るので、それだけでは候補を落とさず、並びの後ろに回す。

並びは、JAN の一致、付属品より本体、似た名前、安さ。「安い順」は価格だけ。楽天市場の候補があるときは、一覧の下に「Supported by Rakuten Developers」を出す。選んだ候補が2件以上のときは、1つの比較グループとして登録する。リストでは商品名につき1枚、URLから登録した商品と同じカードで出す。開くとショップごとに、ショップ名、価格、商品ページ、日本時間の取得時刻、購入済みが出る。候補が1件のときは比較グループを作らず、URLから登録した商品と同じ1件として登録して出す。すでに1件だけのグループが手元のデータベースにあっても、普通の商品と同じカードで出す。左に画像、ショップ、優先度、商品名、価格、外部リンク、ドラッグ、価格推移、編集、購入済み、削除が並ぶ。検索で受け取った画像は、上記3ホストの https だけを候補と商品に残す。商品ページのホストやそれ以外は残さない。リストのカードもこの3ホストだけを出す。ショップ名は1回だけ出す。最安、価格の幅、件数、ショップの開閉は、2件以上のカードの下に出す。出費予定では、複数ショップでもグループ名の見出しやインデントは出さず、普通の商品と同じ平らな行にする。1件のときはURLから登録した商品と同じ行にする。合計と出費予定に数える候補のルールは変えない。購入済みがあればそれ、なければ選んだ候補、それもなければ最安を1回数える。

次のときは、今までの手入力に切り替える。推定できた商品名は最初から入っている。撮った写真は商品画像にしない。

- 候補が0件
- 写真から商品名を推定できない
- 判定の上限に達した
- 店の検索が失敗し、候補が残らなかった

片方の店だけ失敗したときは、取れた側の候補と Amazon の検索結果へのリンクを残す。Amazon の商品 API は使わない。候補は保存してから30分で消える。写真から作った商品は、ページを取りに行く価格チェックには載せない。

## 設定

どちらも値が `true` のときだけオン。それ以外はオフ。

| 変数 | 意味 |
| --- | --- |
| `CAPTURE_ENABLED` | 入口と写真から登録の API。オフのときは入口を出さない |
| `CAPTURE_AI_ENABLED` | 写真からの商品名の推定。`CAPTURE_ENABLED` も `true` のときだけ有効。オフのときは推定せず手入力に戻る。商品名で探す API は `CAPTURE_ENABLED` が `true` なら使える |

キーの値はリポジトリに置かない。シェルか、リポジトリの外にあるモード 0600 のファイル（`CAPTURE_SECRETS_FILE`）にだけ書く。読む場所は `src/lib/capture-secrets.ts`。ログには出さない。

| 名前 | 用途 |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | 写真からの推定 |
| `CLOUDFLARE_API_TOKEN` | Workers AI の Read |
| `YAHOO_SHOPPING_APP_ID` | Yahoo!ショッピングの商品検索 |
| `RAKUTEN_APP_ID` | 楽天市場の商品検索 |
| `RAKUTEN_ACCESS_KEY` | 楽天市場の商品検索。URL には付けない |
| `AMAZON_ASSOCIATE_TAG` | Amazon の検索結果リンクに付けるタグ。商品の取得には使わない |

キーが無い店は検索しない。推定のモデルとニューロンは [写真の見た目から商品を推定する](./capture-ai.md)。

## 端末で試す

`npm run dev` を、同じテールネットの iPhone Safari、Android Chrome、デスクトップのブラウザから開いて、写真の流れを試す。本番のビルドと `next start` はこの設定を見ない。

1. Tailscale Serve で開発サーバのポートをテールネットの HTTPS に出す。例: `tailscale serve --bg 3000`。表示されたホスト名を控える。
2. そのホスト名を `DEV_ALLOWED_ORIGINS` に書いて、開発サーバを起動し直す。カンマ区切りで複数書ける。`https://` やポートが付いていても、ホスト名だけを使う。未設定または空なら、これまでどおりその開発サーバのホスト名と localhost だけを許可する。この変数は development のときだけ有効。
3. iPhone Safari、Android Chrome、デスクトップで、表示された HTTPS の URL を開く。「写真から登録」、またはカードへ1枚ドロップする。スマホは OS の選択シート、デスクトップは「カメラで撮る」と「ファイル/写真を選ぶ」。

同じ LAN の IP から開くときも、その IP を `DEV_ALLOWED_ORIGINS` に入れる。

## 上限

写真の判定は1人につき1分3回、UTC の1日10回。全体で UTC の1日 8,000 ニューロン。回数の残し方は [写真の見た目から商品を推定する](./capture-ai.md)。

店の検索は、待つのを6秒で打ち切る。やり直しはしない。

- Yahoo!ショッピングは、全体で1秒に1回、全体で1分に25回、1人につき1分に5回、1人につき1日に50回。
- 楽天市場は、全体で1秒に1回、1人につき1分に5回、1人につき1日に50回。

## 楽天の1日1回の価格更新

楽天の商品コードがある未購入の商品は、`scripts/check-prices.ts` が24時間ごとに楽天の API で価格を取り直す。この更新は CAPTURE_ENABLED を見ない。RAKUTEN_APP_ID と RAKUTEN_ACCESS_KEY が両方あるときだけ実行する。止めるには、楽天のキーを外す。Yahoo! と、楽天の商品コードが無い商品は、この取り直しには入らない。

## 写真候補の登録とURL入力

写真を選ぶと写真専用の登録画面に切り替わり、通常のURL入力フォームは表示しない。候補にチェックを付けて「選んだ候補を登録」を押すと、候補に保存されている商品URLを自動で使って登録する。URLの入力欄や確認欄は表示しない。複数選択時も各候補の商品URLを自動で使う。選択解除、再検索、写真の選び直しでは古い選択をクリアする。

「URL・手入力に切り替える」で通常の追加フォームへ戻れる。候補が見つからない場合や判定・検索に失敗した場合は、従来どおり商品名を引き継いで手入力を表示する。再試行で候補を検索すると写真専用の画面へ戻る。
